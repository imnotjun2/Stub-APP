# Stub｜生活存根 配色与双语规范 v0.2

v0.2 将 v0.1 的「方向 A：奶油票根」确认为 Stub 的品牌基础，并扩展为浅色、深色两套可直接映射到 Figma Variables、CSS Variables 与 SwiftUI `Color` 的语义 Token。午夜电影票与苔藓档案不再作为并列主方向，后续可保留为专题封面或旅行册模板，但不应改变 App 的基础主题。

## 1. 品牌原则

Stub 的界面应像一张被温柔保存的纸，而不是仿旧滤镜或扫描工具。浅色主题使用奶油纸、砖红印章与深褐墨色；深色主题不是简单反相，而是使用暖黑书桌、深棕纸面与更明亮的金色记忆锚点。真实票根、电影海报、航司 Logo 和用户照片始终保持原色，不做全局反相、变暗或着色，让内容成为两个主题中共同的视觉主角。

品牌色只用于主要操作、选中状态和少量识别锚点。正文、表单值和关键交通信息必须使用高对比文字色；金色只用于日期、短线、页码或短句强调，不用作低字号长段正文。纸张纹理若存在，只能作为低不透明度的质感层，不能降低文字或图片边缘的清晰度。

## 2. 双主题语义 Token

组件只能引用语义 Token，不应在组件内部写死浅色或深色色值。表中深色主题保留奶油品牌的温度，但以暖灰褐代替纯黑与冷灰。

| Token | 浅色 Light | 深色 Dark | 用途 |
|---|---|---|---|
| `bg.canvas` | `#F6F1E7` | `#171410` | App 主背景、时间线与地图外围 |
| `bg.surface` | `#FFFDF8` | `#24201B` | 卡片、底部面板、表单与导航栏 |
| `bg.elevated` | `#FFFFFC` | `#2D2822` | 弹层、菜单、旅行册浮页 |
| `bg.sunken` | `#EEE7DC` | `#100E0C` | 图片占位、地图底槽、输入内层 |
| `text.primary` | `#282421` | `#F6F0E5` | 标题、正文、票据信息与主要图标 |
| `text.secondary` | `#6D6258` | `#C6BCAF` | 辅助说明、日期、次级字段 |
| `text.tertiary` | `#756A60` | `#AAA094` | 非关键字幕、元信息；不用作禁用态 |
| `text.disabled` | `#91877C` | `#7B746C` | 禁用控件与占位提示，不承载关键内容 |
| `text.onBrand` | `#FFF8F0` | `#FFF8F0` | 砖红主按钮上的文字与图标 |

| `brand.pressed` | `#96372B` | `#96372B` | 主操作按下态 |
| `brand.soft` | `#F2D9D1` | `#4A2721` | 标签选中背景、轻提示、品牌弱面 |
| `brand.onSoft` | `#8F3329` | `#FFB6A5` | `brand.soft` 上的文字与图标 |
| `accent.memory` | `#8B5F12` | `#E6BE70` | 月份、回忆短句、旅行册页码与路线锚点 |
| `accent.memorySoft` | `#F3E5C5` | `#493B23` | 金色强调的低权重背景 |

`border.subtle` 只用于装饰性分隔，不应作为输入框或可点击区域的唯一边界。交互轮廓应使用 `border.strong`，或同时提供背景、文字、图标和状态变化。状态色默认作为文字或图标用于 `bg.canvas`、`bg.surface` 上；若要制作整块状态背景，应另建 `status.*Soft` 与 `text.onStatus`，不能直接把表中的状态色当作填充色并假设白字可读。

## 3. 关键对比度与可读性

设计验收以 WCAG AA 为最低目标：常规文字至少 `4.5:1`，大号文字与非文字交互边界至少 `3:1`。以下比值按 Token 的主要组合计算，实际组件仍需在最终背景、字号与字重下复核。

| 组合 | 浅色对比度 | 深色对比度 | 结论 |
|---|---:|---:|---|
| `text.primary` / `bg.canvas` | `13.67:1` | `16.18:1` | 可用于所有正文与标题 |
| `text.secondary` / `bg.canvas` | `5.27:1` | `9.80:1` | 可用于普通字号辅助文字 |
| `text.tertiary` / `bg.canvas` | `4.68:1` | `7.14:1` | 可用于短元信息，不继续降低透明度 |
| `text.onBrand` / `brand.primary` | `4.96:1` | `4.96:1` | 可用于主按钮常规字号 |
| `brand.onSoft` / `brand.soft` | `5.84:1` | `7.79:1` | 可用于标签和筛选状态 |
| `accent.memory` / `bg.canvas` | `4.98:1` | `10.46:1` | 可用于小字号日期与短句 |
| `border.strong` / `bg.surface` | `3.03:1` | `3.13:1` | 可作为交互控件的可见轮廓 |

v0.1 中 `#D6A34A` 金色在奶油背景上的对比度约为 `2.03:1`，品牌副标题与底部说明的部分灰色也只有约 `2.44–2.78:1`。v0.2 因此将浅色金色正文收深为 `#8B5F12`，并把次级文字统一收敛到 `text.secondary` 或 `text.tertiary`。如果仍希望保留更浅的金色，可仅用于不承载信息的线条、纹理或大面积装饰，不能用在日期、正文和按钮标签上。

图片、海报与地图上的文字不能依赖图片本身提供稳定对比。优先把文字放在独立纸面卡片中；确需叠加时，使用局部 `overlay.scrim`、实色标签或从下至上的渐变遮罩，并同时检查图片最亮与最暗区域。深色主题不得通过 `filter: invert()` 处理用户票据、电影海报、食物照片或航司 Logo；只切换界面 Token、状态栏图标与系统控件外观。

## 4. 主题切换规范

外观设置提供「跟随系统 / 浅色 / 深色」三项，英文对应 `System / Light / Dark`。首次使用默认跟随系统；用户手动选择后应持久化，并在下次打开时于首屏绘制前应用，避免先闪出浅色再切到深色。主题切换按钮的触控区域不得小于 `44 × 44 px`，选中状态不能只依赖颜色，还需同时使用勾选、描边或 `aria-pressed` 状态。

实现层建议以 `data-theme="light|dark"` 驱动同名 CSS Variables，系统模式通过 `prefers-color-scheme` 解析。页面同时设置正确的 `color-scheme`，使日期选择器、滚动条和原生表单控件与当前主题一致。切换主题时应覆盖主背景、卡片、表单、底部面板、筛选弹层、Toast、状态栏文字与图标、iOS Home Indicator 及地图控件；上传内容、品牌 Logo 与航司 Logo 不参与主题变色。

主题切换可以使用 `150–200 ms` 的颜色过渡，但在 `prefers-reduced-motion: reduce` 下应关闭。大图、地图和票据不做交叉淡化，以免造成闪烁。深色主题的阴影应降低黑色不透明度并更多依赖 `border.subtle` 区分层级，避免在暖黑背景上形成浑浊的大面积黑影。

## 5. 中文与英文排版

中文界面的产品 UI 优先使用系统无衬线：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Noto Sans SC", sans-serif`；品牌名、月份与旅行册章节可使用 `"Songti SC", "STSong", serif`。英文 UI 使用 `-apple-system, BlinkMacSystemFont, "SF Pro Text", Inter, sans-serif`；英文品牌与编辑性标题使用 `Georgia, "Times New Roman", serif`。在正式发布前若引入品牌字体，需要确认中英文授权与缺字回退，不得依赖某台开发机独有字体。

中文正文建议 `15–17 px`、行高 `1.55–1.70`，英文正文建议 `15–17 px`、行高 `1.40–1.55`。中文正文和按钮不额外增加字距；「生活存根」这类短品牌副标题最多使用 `0.12em` 字距。英文全大写的小标签可使用 `0.04–0.08em`，句式按钮和正文保持正常字距。中文「八月」与英文 `August` 不应强行共享同一固定宽度或字号，可分别使用约 `42 px` 与 `36–38 px`，以保持相同视觉权重。

英文文案通常更长，导航、标签和按钮必须按英文真实文案校验，不通过缩小到不可读字号来硬塞。底部导航优先使用短标签，例如「日常 / 旅行 / 存根墙 / 设置」与 `Life / Trips / Wall / Settings`；主操作可使用「留下一张」与 `Add a Stub`。标签允许内容自适应宽度，筛选面板允许换行，但主导航标签保持单行。

## 6. 语言切换规范

语言切换提供清晰的「中文 / EN」按钮或分段控件，不使用国旗代表语言。控件需要可聚焦、可被读屏识别，并用 `aria-pressed` 或单选语义表达当前语言。用户选择应本地持久化；切换后设置文档 `lang` 为 `zh-CN` 或 `en`，同时更新页面标题、按钮、表单标签、占位符、错误提示、Toast、图片替代文字与无障碍名称。

类别、标签和票据类型在数据层使用稳定 ID，例如 `movie`、`travel.flight`、`movie.imax`，界面层再映射为「电影 / Movie」「机票 / Flight」「IMAX / IMAX」。不得把「电影」「旅行」等中文显示值直接作为持久化枚举，否则切换英文后会导致筛选、迁移和统计逻辑混乱。日期与月份使用 `Intl.DateTimeFormat` 按当前语言格式化，不手写「八月」或 `August`。

语言切换只翻译产品界面和内置示例，不自动翻译用户填写的标题、笔记、自定义标签与旅行册名称。若示例数据需要双语展示，应分别维护 `zh-CN` 与 `en` 文案，而不是在运行时猜测翻译。品牌主名 `Stub` 在两种语言中保持不变；中文副标题可显示「生活存根」，英文副标题建议使用 `Life, kept.`，避免生硬直译为 `Life Stub`。

## 7. 使用比例与组件落地

浅色主题继续遵循约 80% 奶油中性背景、15% 真实内容与纸面、5% 品牌及状态色。深色主题将比例理解为 75% 暖黑画布、20% 深棕纸面与真实内容、5% 砖红和金色锚点。主按钮是全局最饱和的界面元素；金色强调不制作整张高饱和卡片，砖红也不用于大面积页面背景。

首轮落地时，首页、上传确认页、存根详情、旅行地图、旅行册、存根墙、筛选弹层与设置页必须同时检查浅色、深色、中文、英文四种组合。验收不能只看静态色板，还需覆盖真实票据偏白、电影海报偏暗、航司 Logo 高饱和和用户照片颜色复杂的情况。

版本记录：v0.2 选择奶油票根为唯一基础品牌方向，新增深色主题、可读性修正、主题切换规则与中英文排版/本地化规范。
